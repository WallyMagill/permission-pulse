# v0.7.2 release runbook — human gates, screenshots, publication

One session on a Tahoe Mac takes you from "code complete" to "published
release". Everything automated has already run; this file is the human
half. Work top to bottom. If any step fails, stop and fix before tagging.

**Preconditions** (already verified in-session, re-verify if the tree moved):
`main` is clean at the release commit, all four package suites pass,
`scripts/smoke-test.sh --keep --no-launch` exits clean, and
`Config/Version.xcconfig` reads `0.7.2` / build `12`.

## Step 1 — Hand-test checklist (A–V8)

Run:

```bash
scripts/smoke-test.sh --keep
```

(without `--no-launch`, so the app opens). The script re-runs every
automated gate and then prints the canonical **A–V8 human checklist** —
that printed list is the single source of truth; work through it. Notes:

- Item **F** (test-notification banner label) and item **J** (VoiceOver on
  the menu-bar icon) are the two known-risk items on an ad-hoc-signed
  bundle. If either fails, that's a release decision, not a shrug — see
  CLAUDE.md "Known fragile surfaces" for the documented fallback.
- Item **R** changed in v0.7.2: the app now pins its accent to brand blue.
  Interactive elements must **ignore** a non-blue system accent.
- To make Recent Changes non-empty for items G/U5, run
  `scripts/seed-diff.sh` then click Refresh.

## Step 2 — v0.7.2-specific eyeball items (new this release)

1. **App icon** (first release with one): check it renders crisply in
   Finder (list + gallery view of the built `.app`), the Dock-less About
   panel, System Settings → Privacy & Security → **Full Disk Access**
   (the row users are told to find), Login Items after enabling launch
   at login, and the Gatekeeper "Apple could not verify…" dialog.
2. **Plural copy**: with the seeded diff producing exactly one change,
   the dropdown must read "1 change since your last review" — no
   "1 changes" anywhere (dropdown, Overview, sidebar VoiceOver labels).
3. **Badges in dark mode**: Mock/Live/Enabled/Disabled badges are fixed
   pale tints — confirm they read as intentional chips on dark cards,
   not glowing patches.
4. **Welcome window with a non-blue system accent**: hero shield,
   feature icons, and numbered step circles must all render brand blue —
   one brand color, no pink/graphite bleed-through.
5. **Digest tab at large Dynamic Type**: crank text size; the grouped
   form must scroll to reach every control (it is List-backed — if it
   clips instead of scrolling, that's a bug).
6. **Gatekeeper first launch on a fresh account**: use a separate macOS
   user account that has never opened the app; follow the README's
   install steps 1–4 exactly as written and confirm they match reality.

## Step 3 — Screenshots for the README

Take these during the same session, **light and dark** for each (⌃F5
appearance toggle between shots; use consistent window sizes; hide
personal data — scan results show your real installed apps, so screenshot
on an account whose app list you're comfortable publishing):

| # | Shot | Setup |
|---|------|-------|
| 1 | Menu-bar dropdown with live status rows | seed-diff + one stale app for non-empty counts |
| 2 | Overview page | after a completed FDA scan |
| 3 | Permission Inbox with inspector open | select an app with several grants |
| 4 | Recent Changes (What Changed) | seeded diff visible |
| 5 | Stale Apps | at least one candidate |
| 6 | Preferences → Digest tab | toggle on, schedule visible |

Save as `docs/images/<nn>-<name>[-dark].png`, target ≤ 400 KB each
(use `sips -Z 1600` to cap width; PNG). Add to the README under a
"Screenshots" section between **Status** and **Install**, then commit
(`docs: add v0.7.2 README screenshots`).

## Step 4 — Package, verify, tag, publish

Exactly per `docs/06-distribution.md` — from the clean release commit:

```bash
scripts/smoke-test.sh --keep --no-launch
scripts/package-release.sh 0.7.2 /tmp/permission-pulse-v0.7.2
scripts/verify-release.sh \
  /tmp/permission-pulse-v0.7.2/PermissionPulse-v0.7.2.app.zip 0.7.2 12
```

Then, manually:

1. Confirm the manifest's `gitSHA` equals `git rev-parse HEAD`.
2. Tag that exact commit `v0.7.2`; push the branch and tag.
3. Create the GitHub release; upload the zip, `.sha256`, and manifest.
4. Download all three into a fresh directory; `shasum -a 256 -c` the
   sidecar; rerun `scripts/verify-release.sh` on the downloaded zip.
5. Publish; then amend the v0.7.1 release notes to point forward.
   Never modify or delete the v0.7.1 asset.
6. Update `docs/09-roadmap.md` (mark v0.7.2 released with today's date)
   and the README **Status** section; commit and push.

## Release notes draft (hand-edit before publishing)

> ## Permission Pulse v0.7.2
>
> The largest release since v0.5.0 — a full app-quality pass, a visual
> overhaul, and the app's first icon.
>
> **New**
> - App icon (brand-blue shield + pulse) — no more blank icon in Finder,
>   Gatekeeper, and System Settings.
> - Export the current permission state to JSON or Markdown.
> - Launch at login (Preferences → General, via `SMAppService`).
> - Recent Changes now tracks TCC authorization *transitions* (e.g.
>   Allowed → Limited), included consistently in badges, search,
>   dismiss/snooze, and the weekly digest.
> - Native redesign: Overview page, non-modal inspectors, sidebar
>   navigation, Settings-style Preferences tabs.
>
> **Improved**
> - Scanner results are now explicitly complete / degraded / failed;
>   degraded reads never masquerade as complete and never pollute
>   snapshot history.
> - Stable app identities (`bundle:` / `path:`) — separate path-only
>   clients no longer collapse together; stale-app dismissals migrate.
> - Snapshot schema v5 preserves LaunchAgent disabled state without
>   corrupting v4 history.
> - Grammar: count strings now pluralize ("1 change", not "1 changes").
> - Accessibility: destination-specific VoiceOver hints in the dropdown,
>   unit-bearing sidebar badge labels, Dynamic-Type-scaling row icons.
> - One consistent brand accent across the app regardless of the
>   system accent color.
>
> **Install**: download `PermissionPulse-v0.7.2.app.zip`, unzip, drag to
> Applications. First launch requires the Gatekeeper "Open Anyway" step
> (unsigned app — see the README). Verify the download against
> `PermissionPulse-v0.7.2.app.zip.sha256`.
