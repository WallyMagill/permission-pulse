# v0.7.2 release runbook — human gates, screenshots, publication

One session on the release Mac (macOS 27; repeat the eyeball items on a
macOS 26 Mac if one is available) takes you from "code complete" to
"published release". Everything automated has already run; this file is the human
half. Work top to bottom. If any step fails, stop and fix before tagging.

**Preconditions** (already verified in-session, re-verify if the tree moved):
the release commit is clean (it may still be on `release/v0.7.2` before
that branch merges), CI is green on both matrix legs (macOS 26 / Xcode
26.5 and macOS 27 / Xcode 27.2) for that exact SHA, all four package
suites pass,
`scripts/smoke-test.sh --keep --no-launch` exits clean, and
`Config/Version.xcconfig` reads `0.7.2` / build `12`.

## Step 1 — Hand-test checklist (A–X8)

Run:

```bash
scripts/smoke-test.sh --keep
```

(without `--no-launch`, so the app opens). The script re-runs every
automated gate and then prints the canonical **A–X8 human checklist** —
that printed list is the single source of truth; work through it. Notes:

- Item **F** (test-notification banner label) and item **J** (VoiceOver on
  the menu-bar icon) are the two known-risk items on an ad-hoc-signed
  bundle. If either fails, that's a release decision, not a shrug — see
  CLAUDE.md "Known fragile surfaces" for the documented fallback.
- Item **R** changed in v0.7.2: the app now pins its accent to brand blue.
  Interactive elements must **ignore** a non-blue system accent.
- To make Recent Changes non-empty for items G/U5, change one real
  permission (on macOS 27: Screen Recording or Accessibility for one
  app) in System Settings, then click Rescan.

## Step 2 — v0.7.2-specific eyeball items (new this release)

1. **App icon** (first release with one): check it renders crisply in
   Finder (list + gallery view of the built `.app`), the Dock-less About
   panel, System Settings → Privacy & Security → **Full Disk Access**
   (the row users are told to find), Login Items after enabling launch
   at login, and the Gatekeeper "Apple could not verify…" dialog.
2. **Plural copy**: with exactly one unreviewed change,
   the dropdown must read "1 change since your last review" — no
   "1 changes" anywhere (dropdown, Overview, sidebar VoiceOver labels).
3. **Badges in dark mode**: Mock/Live/Enabled/Disabled badges are fixed
   pale tints — confirm they read as intentional chips on dark cards,
   not glowing patches.
4. **Welcome window with a non-blue system accent**: hero shield,
   feature icons, and numbered step circles must all render brand blue —
   one brand color, no pink/graphite bleed-through.
5. **Notifications tab at large Dynamic Type**: crank text size; the grouped
   form must scroll to reach every control (it is List-backed — if it
   clips instead of scrolling, that's a bug).
6. **Gatekeeper first launch on a fresh account**: use a separate macOS
   user account that has never opened the app; follow the README's
   install steps 1–5 exactly as written and confirm they match reality.
7. **Upgrade from v0.7.1**: install v0.7.1 from its GitHub release,
   grant it Full Disk Access, then replace it in `/Applications` with the
   v0.7.2 candidate. Launch it and confirm the "Full Disk Access was
   turned off" window opens, then follow its steps (README install
   step 5) and confirm it reports "Full Disk Access is back on" or,
   after Reopen, Permissions shows live data. Confirm the history was
   migrated, not lost: Recent Changes shows no "History Unavailable" or
   "History Is Damaged" state, and Copy Diagnostics reports
   `schemaVersion: 7`.

## Step 3 — Screenshots for the README

Take these during the same session, **light and dark** for each (⌃F5
appearance toggle between shots; use consistent window sizes; hide
personal data — scan results show your real installed apps, so screenshot
on an account whose app list you're comfortable publishing):

| # | Shot | Setup |
|---|------|-------|
| 1 | Menu-bar dropdown with live status rows | one changed permission + one stale app for non-empty counts |
| 2 | Overview page | after a completed FDA scan |
| 3 | Permissions with inspector open | select an app with several grants |
| 4 | Recent Changes, Since Last Review | one changed permission visible |
| 5 | Stale Apps | at least one candidate |
| 6 | Preferences → Notifications tab | change alerts and digest on, schedule visible |

Save as `docs/images/<nn>-<name>[-dark].png`, target ≤ 400 KB each
(use `sips -Z 1600` to cap width; PNG). Add to the README under a
"Screenshots" section between **Status** and **Install**, then commit
(`docs: add v0.7.2 README screenshots`).

## Step 4 — Package, verify, tag, publish

Exactly per `docs/06-distribution.md` — from the clean release commit:

```bash
scripts/smoke-test.sh --keep --no-launch
scripts/package-release.sh 0.7.2 /tmp/permission-pulse-v0.7.2
scripts/verify-release.sh \
  /tmp/permission-pulse-v0.7.2/PermissionPulse-v0.7.2.app.zip 0.7.2 12
```

Then, manually:

1. Confirm the manifest's `gitSHA` equals `git rev-parse HEAD`.
2. Tag that exact commit `v0.7.2`; push the branch and tag.
3. Create the GitHub release; upload the zip, `.sha256`, and manifest.
4. Download all three into a fresh directory; `shasum -a 256 -c` the
   sidecar; rerun `scripts/verify-release.sh` on the downloaded zip.
5. Publish; then amend the v0.7.1 release notes to point forward.
   Never modify or delete the v0.7.1 asset.
6. Update `docs/09-roadmap.md` (mark v0.7.2 released with today's date)
   and the README **Status** section; commit and push.

## Release notes draft (hand-edit before publishing)

> ## Permission Pulse v0.7.2
>
> The largest release since v0.5.0: change history that keeps itself up
> to date, optional change alerts, macOS 27 support, a redesigned
> window, and the app's first icon.
>
> **New**
> - History records itself. The app checks again when your Mac wakes,
>   at the start of each day, and when you open it, and keeps a record
>   whenever something changed, so Recent Changes shows a new permission
>   the same day without a manual Rescan.
> - Recent Changes has two views. **Since Last Review** lists everything
>   since you last looked; leaving the page or choosing **Mark All
>   Reviewed** clears it. **Last 7 days** shows the past week. Since
>   Last Review replaces the old "Yesterday" view.
> - **Change alerts** (optional, Settings → Notifications): a
>   notification when Permission Pulse finds a change.
> - Permission changes such as Allowed → Limited now appear in Recent
>   Changes, the badges, search, and the weekly digest.
> - Remote Desktop and Endpoint Security permissions are now listed.
> - A permission whose app has been deleted is marked "App not found on
>   this Mac".
> - Background Items names each item's type: login item, app agent,
>   legacy agent or daemon, background tasks, and Spotlight, QuickLook,
>   and Dock tile extensions.
> - Launch Agents rows show the program each job runs and who it runs
>   for, and flag a job whose program no longer exists.
> - **Check for Updates…** in the menu-bar dropdown and in Settings →
>   General opens the Releases page in your browser. Settings → General
>   → About shows the version.
> - Export to JSON or Markdown. The export says what could and could not
>   be read, and which app and macOS versions produced it.
> - Launch at login (Settings → General), showing its real status,
>   including when macOS needs you to approve it in Login Items.
> - Settings → Data can bring back dismissed changes and skipped stale
>   apps. **Copy Diagnostics** copies the app's own status for a bug
>   report; it never includes other apps' names or paths.
> - The dropdown shows when the last check ran, and the menu-bar icon
>   shows live microphone or camera use ahead of anything else.
> - Double-clicking Permission Pulse in Finder while it runs opens its
>   window.
> - Redesigned window: an Overview page, a sidebar, side inspectors,
>   and Settings-style tabs. App icon (a blue shield with a pulse line)
>   in Finder, Gatekeeper, and System Settings.
>
> **macOS 27**
> - Background Items works again (macOS 27 changed where it keeps them).
> - macOS 27 no longer lets any app read per-user permissions (Camera,
>   Microphone, Files and Folders, Automation, and others). Permission
>   Pulse says so on each screen and shows the system-level permissions
>   it can still read: Accessibility, Full Disk Access, Input Monitoring,
>   Screen Recording, Remote Desktop, and Endpoint Security. Searching
>   for a hidden one, such as Camera, explains why it is missing and
>   offers its System Settings pane.
> - History recorded on macOS 26 is compared with macOS 27 for the
>   system-level permissions, and Recent Changes says so.
>
> **Fixed**
> - A launch daemon whose file only the system can read (such as a VPN
>   helper) no longer leaves Launch Agents permanently flagged as a scan
>   problem. It is listed as "Details unreadable".
> - A job turned off with `launchctl` or in System Settings → Login
>   Items now shows as disabled in Launch Agents.
> - Empty launchd files (such as Google Keystone's leftovers) and
>   shortcuts to deleted files no longer flag Launch Agents.
> - Recent Changes no longer shows false "removed" rows when a section
>   could only be partly read. It names each section it could not
>   compare and says why.
> - Renamed or re-dated items no longer show up as changes; only what
>   the app displays (a permission's state, an item's type and on/off
>   state) counts.
> - A background item registered for several users is no longer merged
>   into one row.
> - The weekly digest no longer repeats an old summary; it is refreshed
>   after every check.
> - Microphones and cameras connected after launch are now watched, and
>   unplugging one while it is in use no longer leaves the indicator on.
> - Stale Apps no longer flags command-line tools as unused after a
>   macOS update, says "Last modified" when it only knows the file
>   date, lists each permission once, and no longer says every app was
>   "used recently" when it had nothing to check.
> - Overview shows "—" instead of "0" for a section that has never
>   been read.
> - Two apps known only by their location are no longer merged into
>   one, and skipped stale apps stay skipped.
> - Only one copy of Permission Pulse runs at a time, so two copies
>   cannot write to the same history.
> - A history file from a newer version, or a damaged one, gets its own
>   message in Recent Changes.
> - Counts read correctly ("1 change", not "1 changes"); VoiceOver
>   hints name where each dropdown row goes; one brand color regardless
>   of the system accent color.
>
> **Updating from v0.7.1**
> - macOS turns Full Disk Access off for Permission Pulse when the app
>   is replaced, because the grant is tied to the old build's
>   signature. The first time v0.7.2 finds it off, it opens a window
>   with the steps: turn Permission Pulse back on in System Settings →
>   Privacy & Security → Full Disk Access (off and on again if it
>   already looks on), then come back. It checks again and offers to
>   reopen the app if macOS needs that.
> - Your history is kept and upgraded on first launch.
>
> To install: download `PermissionPulse-v0.7.2.app.zip`, unzip it, and
> drag the app to Applications. The first launch needs the Gatekeeper
> "Open Anyway" step, because the app is not signed with a paid Apple
> Developer ID (see the README). Verify the download against
> `PermissionPulse-v0.7.2.app.zip.sha256`.
